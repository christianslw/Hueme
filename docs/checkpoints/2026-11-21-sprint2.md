## Contracts locked this sprint

- `StudioRuntime` is the single live session. Rig edits mutate a working copy;
  `POST /api/rig/save` persists atomically. Activating/switching/deleting a
  dirty working copy requires `force=true`; the UI asks first.
- Show edits go through `ShowStore.commit`; one request = one undo snapshot.
- Preview frames: `HUE1`, `<4sIfI>` header, then `voxel_count * 3` RGB bytes.
- Invalidations are JSON text messages on `/ws/preview`; the UI refetches
  `/api/studio/state`. MCP will publish through the same bus in Sprint 3.
- The UI is vanilla ES modules. No framework, no build step, no CDN.
- No `alert()` / `confirm()`; destructive actions use native `<dialog>` modals,
  errors use toasts.

## Deliberate deviations / limits

- Viewport is a Canvas2D perspective projection, not Three.js. Works offline
  and renders room, fixtures, additive cones, floor pools, selection and camera
  presets. Upgrade if true volumetric depth is needed.
- Viewport drag writes `transform.translate`; Shift constrains to Z. Axis
  handles are drawn but not draggable yet.
- Timeline has no waveform until the AudioBlueprint exists in Sprint 3.
- HAL is still opt-in and not wired to the preview ticker. Preview gain,
  blackout and transport are preview-only for now.
- MCP drawer is an honest placeholder until Sprint 3.
- No authentication; bind to loopback or put behind a trusted proxy.
