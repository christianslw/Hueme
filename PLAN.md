# Hueme — Implementation Plan

Real-time reactive lighting for low-density fixtures (2–10 spots/zone), with
audio-reactive effects, hot-reloaded effect plugins, and Hue/DDP/E1.31/WLED
output. This plan is the handoff document for implementation. The existing
`hue_gateway_web.py` is the reference; keep it in the repo until feature
parity is confirmed.

---

## 2. Decisions (lazy defaults)

| Topic | Decision | Why |
|---|---|---|
| Language | Python 3.11+ (dev 3.13) | Existing code, no rewrite |
| Web | `http.server.ThreadingHTTPServer` + vanilla JS/canvas | No framework/build step |
| Concurrency | Threads + `queue`/locks | Blocking `parec`/TCP sockets; asyncio buys nothing here |
| FFT | `numpy` | Stdlib has no FFT; 4 bands + flux on 512 samples is trivial in numpy |
| MQTT | `paho-mqtt` | Only sane Python client |
| Effects | Plain `.py` files + a **persistent sandbox subprocess** | Requirement: a crashing/hanging effect must not kill the engine |
| Config | One human-readable JSON file, atomic writes | Requirement; no DB |
| Frontend | 5 tabs, one HTML file, no CDN | Works offline in container |
| Radar | Deferred, config no-op | User instruction |

**Dependencies:** `numpy`, `paho-mqtt`. Nothing else. Tests use `unittest`.

## 5. Runtime flow and latency budget

```
Audio thread (read block + FFT inline) ──features──> Engine render thread
                                                          │
                               snapshot pixels per group  ├──> Hue driver (MQTT)
                                                          ├──> DDP / E1.31 / WLED (UDP)
                                                          └──> in-memory inspector
UDP input thread(s) ──latest pixels──> group.input_pixels (overrides effect when fresh)
Web thread ──> config/status/effects API (never blocks the render loop)
```

- One render tick at `max(group.fps)` (default 30). Each group renders when due;
  otherwise its last pixels are reused. This keeps one clock.
- Precedence per group: fresh UDP input (`now-last_rx <= idle_timeout`) wins;
  else if `effect.enabled`, render effect; else black/idle.
- All state snapshots taken under a lock and copied; no lock held while sending.
- Drivers run synchronously in the render thread for now (UDP sends are
  non-blocking enough at 2–50 pixels). If MQTT publish blocks, paho queues in
  its own network thread; `publish()` is non-blocking.
- **Latency measurement point:** timestamp when `AudioSource.read()` returns a
  block, then timestamp immediately before the driver writes the corresponding
  frame. Exclude upstream Snapcast/Pulse buffering; include DSP, render, and
  send. Keep p50/p95 over the last 120 frames in `/api/status`.
- Budget at 48 kHz: 512-sample block = 10.7 ms; FFT+features < 3 ms; render <
  5 ms; send < 5 ms; 30 fps pacing worst case 33 ms. p95 target < 35 ms.
  If 25 fps is configured, document that pacing alone can exceed 35 ms.

### Audio DSP spec (`audio.py`)

- Mono `float32`; stereo averaged. Resample not needed (require 44.1/48 kHz;
  reject others with a clear error).
- Ring buffer; every hop = `block` samples, window last `window` (1024) with
  Hann, `np.fft.rfft`, magnitude spectrum.
- Bands: sub 20–120, snare 150–900, mid 400–2800, high 3000–12000 Hz.
- Band level: RMS of bins normalized by a long-term per-band EMA (tau ~4 s),
  clamped 0..1, multiplied by `sensitivity`. This mirrors the current proven
  behavior and adapts across genres.
- AGC: time-domain RMS, EMA tau `tau_s`; gain = clamp(target/max(rms,eps),
  0.25, 8). Do **not** boost when `rms < silence_db` (no dead-room noise).
- Onset: spectral flux per band = `sum(max(0, mag-prev_mag))`, normalized.
  Threshold = `median(last ~1 s) * k + delta`; kick on sub band with 120 ms
  refractory and level > 0.3; snare on 150–900 with 70 ms refractory.
  Onset sets envelope to 1.0 (attack 0); release `exp(-dt/tau)` with tau
  80 ms kick / 50 ms snare. Expose `kick` (bool, one frame) and `kick_env`.
- BPM: EMA over kick intervals in 0.25–1.3 s (port current logic).
- Output feature dict keys (stable API for effects):
  `bass, snare, mids, highs, kick, kick_env, snare_env, bpm, rms, agc_gain,
  latency_ms`.

Sources:

- `parec`: subprocess, `--raw --format=s16le --rate --channels --latency-msec=30`,
  non-blocking reconnect with exponential backoff (1→8 s), `stderr=DEVNULL`.
- `snapcast`: TCP connect, read exact `block*channels*2` bytes, s16le→float32.
  Reconnect with backoff. Port default 4953 per spec.
- `wav`: stdlib `wave`, loop at EOF; for tests/demo.
- `synthetic`: generated kick (60 Hz sine burst) + snare (noise burst) + bass
  line at 128 BPM, plus slow gain changes to exercise AGC. No external files.
- `auto`: win32 → synthetic; else parec if `shutil.which("parec")`.
- Windows system-audio capture is **not** in scope; add `sounddevice` later only
  if asked. (Deliberate simplification.)

## 6. Effect plugin contract (`effects/*.py`)

```python
META = {"id": "club_tech", "name": "Club Tech", "description": "Kick anchors + snare fill"}
PARAMS = [
    {"key": "color",      "type": "color",  "default": [255, 0, 85]},
    {"key": "color2",     "type": "color",  "default": [0, 240, 255]},
    {"key": "brightness", "type": "range",  "min": 0, "max": 1, "step": 0.05, "default": 1.0},
    {"key": "bass_boost", "type": "range",  "min": 0.5, "max": 3, "step": 0.1, "default": 1.3},
]

def setup(state):
    state.setdefault("scanner_pos", 0.0)   # optional

def render(ctx):
    # ctx keys: n, now, dt, features, params, state, positions, utils
    # return: list of (r,g,b), exactly n entries, 0..255
    ...

def teardown(state):
    pass
```

- `state` is a plain dict persisted across frames (scanner position, peak
  hold, beat counter). It is sent to/from the sandbox each frame.
- `positions` is `[(x,y), ...]` for fixtures, so effects can be spatial.
- `utils` is injected by the sandbox: `lerp(a,b,t)`, `scale(c,f)`, `add(a,b)`,
  `hsv(h,s,v)`, `palette(name)`, `clamp`. Bundled effects use these; no imports
  from the app.
- Schema types the UI must render: `range`, `number`, `color`, `select`,
  `bool`. `select` has `options: [[value,label], ...]`.
- Bundled effects (port the algorithms from `_render_music_effect`, keep the
  low-pixel behavior):
  `club_tech`, `bass_cannon` (+ peak-hold state), `band_matrix`, `ping_pong`,
  `strobe_drop`, `ambient_uplight`, `dim2warm` (CCT dim-to-warm), `diagnostic_chase`,
  `rainbow`, `breathe`, `solid`.
- Hot reload: parent polls mtimes every `poll_s`; UI save triggers reload
  immediately. Reload is atomic: if compile/load fails, keep the old version
  and surface the error in `/api/effects`.
- Validation: `compile(source, path, "exec")`; reject missing `META`/`render`,
  non-list `PARAMS`, unknown param types, duplicate keys. Return
  `{ok:false,error,line,col}`.

### Sandbox (`sandbox.py`)

- One persistent `multiprocessing.Process` for all effects, `spawn` context
  (Windows + Linux consistent). Parent↔child `Pipe`.
- Load/reload message: `{"op":"load","effects":[{"id":..., "source":"...","params":[...]}]}`
  → child replies `{"op":"loaded","errors":{id: msg}}`. Invalid effects keep
  their previous source.
- Parent sends one render message per tick:
  `{"op":"render","frame":N,"requests":[{"id":..., "n":..., "now":..., "dt":..., "features":{...}, "params":{...}, "state":{...}}]}`
  Child replies `{"op":"rendered","frame":N,"results":[{"id":..., "pixels":[[r,g,b],...], "state":{...}, "error":null}]}`.
- Parent waits with `conn.poll(timeout_ms / 1000)`; on timeout/EOF it terminates and
  restarts the child, marks the tick as failed, and reuses last good pixels.
  Restart counter and last error exposed in `/api/effects`.
- Child executes source with a restricted `__builtins__` (no `open`, `exec`,
  `eval`, `__import__`, `os`, `subprocess`, `socket`); allow `math`, `random`,
  `colorsys` via injected `utils`. This is a **fault boundary, not a security
  boundary** for untrusted code; document that.
- Linux: `resource.setrlimit(RLIMIT_AS, 128 MB)` in the child. Windows: no
  rlimit; timeout+restart is the ceiling. Mark with a `ponytail:` comment.
- Fallback on plugin failure: render a safe black frame (or last good frame if
  < 500 ms old) and log once per effect, not per frame.

## 7. Transport drivers (`drivers.py`)

Common: `start()`, `send(snapshot)`, `stop()`, `status() -> {tx, errors,
last_error, last_hex, last_len}`. All errors are caught and logged; a broken
driver degrades, never crashes the render loop.

Snapshot is a stable list: `[(group_id, fixture_index, (r,g,b)), ...]` plus
`{group_id: [(r,g,b)...]}` for UDP drivers. Build once per tick.

### Hue (Z2M / ZCL 0xFC01)

- Port the wire builders from the stub exactly:
  `record`, `frame_payload`, `sync_payload`, `zclcommand_msg`, `rgb_to_xy`,
  `clamp_gamut`, `quant_xy`.
- Publish to `{base_topic}/{proxy}/set` with the zclcommand JSON; use paho's
  network loop thread. `connect_async` + retry; buffer only the latest frame.
- Session lifecycle: when the first group becomes active, publish optional
  light-balance attribute and start frames; when all inactive for
  `idle_timeout`, publish `sync_payload` stop (cmd `CMD_SYNC_STOP`).
- Consolidation: flatten active fixtures in config order, chunk by
  `max_fixtures_per_frame` (10). Chunk 0 → `proxies[0]`; chunk k →
  `proxies[k % len]`. If only one proxy, alternate chunks across frames
  deterministically (frame counter) so every fixture gets updated at a reduced
  rate. Never exceed 10 records per publish.
- Counters: frames, fixtures, chunks, publishes, errors. Hex of the last ZCL
  `data` bytes (first 64) for the inspector.
- **Unknown constants** (`CLUSTER`, `MFC`, `ATTR_LIGHT_BALANCE`,
  `smoothing_for_fps` table) must not be invented silently. Put them in
  `drivers.py` as named constants with a comment `# VERIFY ON HARDWARE` and
  make `light_balance` optional (`hue.light_balance: false` by default) until
  verified. See §11.

### DDP

- UDP to `outputs.ddp.host:port`. Header: flags `0x40`, seq, data type `0x01`,
  source id, offset u32 BE, length u16 BE. Send RGB payload with offset
  `pixel_index*3`; chunk ≤ 1400 bytes. Sequence per group.

### E1.31 / sACN

- Build root/framing/DMP layers, 638-byte slot array, start code 0, sequence,
  universe per 170 pixels (510 channels). Unicast to `outputs.e131.unicast` if
  set, else multicast `239.255.(u>>8).(u&255)` port 5568. Priority default 100.
- Receiving side already exists; port the parser unchanged.

### WLED

- UDP DRGB (`0x02`) for ≤ 490 pixels, DNRGB (`0x04`) for larger, WARLS (`0x01`)
  for sparse updates. Default DRGB. No HTTP JSON API / mDNS discovery in v1
  (deferred; see §10).

### UDP receivers

- **E1.31 is one global receiver** on UDP 5568 (multicast join for every
  enabled universe), as in the current `GatewayManager.start_e131`; dispatch a
  parsed packet to the group whose universe range covers it.
- DDP, RAW and WLED are per group (each group owns its port); one `select`
  thread for them as today. Parse DDP/E1.31/WLED WARLS/DRGB/DNRGB/RAW; write
  latest pixels + `last_rx`.
- Unique-port validation happens in config validation before sockets bind.
- Bad packets increment `bad`; never throw.

## 8. HTTP API (`web.py`)

All JSON; no auth (LAN-only; bind default `0.0.0.0`, document exposure risk).
Responses must be produced from snapshots and never block the render loop.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | `{ok, uptime_s, version}`; container healthcheck |
| GET | `/api/config` | current config + Z2M devices |
| PUT | `/api/config` | validate, atomic save, hot-apply (audio/drivers/effects) |
| GET | `/api/status` | audio features, groups (active/pixels/effect/error), engine fps/µs/latency |
| GET | `/api/effects` | list: id, meta, params, error, loaded_at |
| GET | `/api/effects/{id}` | `{source}` |
| PUT | `/api/effects/{id}` | validate + save + reload; 400 with line/col |
| POST | `/api/effects/{id}/reload` | force reload |
| POST | `/api/effects/reload` | reload all |
| GET | `/api/protocols` | driver counters + last hex/length |
| POST | `/api/z2m/scan` | bridge device discovery (2 s timeout) |
| POST | `/api/audio/reconnect` | restart the current source |
| GET | `/api/logs` | last 200 log lines |

- Config write: `tempfile` + `os.replace`, `*.bak` once per save.
- Validation: types/ranges; unique input ports; known effect ids; fixture addr
  parses via `int(addr,0)`; `max_fixtures_per_frame <= 10`; proxy names exist.
- Applying config: restart only the affected components (audio source if
  changed, receivers if ports changed, drivers if outputs changed, effects if
  dir/params changed). Never restart the process from the API.

## 9. Web UI (`static/`)

One page, five tabs, plain CSS (dark), no external resources.

1. **Dashboard**
   - Connection dots (audio, MQTT/Hue, each output).
   - Audio telemetry: four bars (sub/snare/mid/high), kick/snare pills, BPM,
     RMS/AGC gain, sensitivity slider (debounced PUT).
   - Group cards: on/off, effect select, auto-generated params from schema,
     canvas visualizer (spots at x/y, gamma-corrected fill, glow halo, decay
     from last frame), active badge, FPS.
   - Canvas draws spots as circles sized by count; strips (n>16) as a line.
2. **Fixtures**
   - Per group: drag-and-drop ordering (HTML5 draggable, persist on drop),
     name/address/x/y inputs, proxy radio, add-from-Z2M, delete.
   - Canvas drag sets x/y; click spot selects row.
   - Warn inline when total Hue fixtures exceed 10 or input ports collide.
3. **Effects**
   - List with metadata/error badges; textarea editor (monospace, tab inserts
     spaces); Save & Reload; server-side syntax error with line/col; param
     preview rendered from `PARAMS`; "New from template" optional.
   - Linting = server `compile()`; no CodeMirror dependency. Deliberate
     simplification; add a vendored editor only if the textarea proves painful.
4. **Inspector**
   - Engine FPS, loop µs, audio→send p50/p95, per-driver TX/error counters,
     last hex dump, log tail, copy-payload button.
5. **Settings**
   - Audio source/device/rate/AGC, MQTT, Hue enable/proxies/frame size/
     smoothing/brightness mode, DDP/E1.31/WLED targets, effects dir/timeout.
   - Save applies without process restart.

Polling: `/api/status` every 100 ms; `/api/protocols` every 500 ms; config and
effects on change only. Use `requestAnimationFrame` for canvas, fed by the
latest poll. No framework, no build.

## 12. Fault tolerance and observability rules

- Every long-running thread/loop has a top-level `try/except` with backoff and
  logging; no bare exceptions that kill a thread.
- Audio disconnect → features decay to zero after 1.5 s → groups go idle; the
  source reconnects in the background.
- MQTT/driver failure → driver marked degraded, retried, engine keeps running.
- Effect crash/hang → sandbox restart, fallback frame, error badge.
- Config save failure → old config stays active; return 400/500 with reason.
- Logging: `logging` to stdout, level configurable; in-memory `deque(500)` for
  `/api/logs`. Include frame drops, reconnects, driver errors, sandbox restarts.
- Latency and counters are exposed; no external metrics stack in v1.

## 15. Deliberate simplifications (ceilings and upgrade paths)

These are conscious cuts, not oversights. Each gets a `ponytail:` comment in
the code naming the ceiling and upgrade path.

| Simplification | Ceiling | Upgrade when |
|---|---|---|
| One effect sandbox for all groups | A hung effect stalls all plugin effects for that tick; child restart costs ~100 ms | Effects serve many groups or untrusted authors: process per effect |
| Drivers send synchronously in the render thread | A slow broker/socket can push a frame past 35 ms | p95 latency regresses: dedicated sender thread + latest-frame queue |
| Linting = server-side `compile()` in a textarea | No autocomplete/inline squiggles | Textarea editing becomes the bottleneck: vendor CodeMirror (no CDN) |
| No Windows system-audio capture | Dev testing uses synthetic/WAV/Snapcast | User needs desktop audio on Windows: add `sounddevice` |
| One global E1.31 socket | No per-universe send pacing | Packet loss on large setups: per-target pacing/queue |
| No auth/TLS on the web API | Anyone on the LAN can edit config | Exposed beyond LAN: token + TLS reverse proxy |
| WLED UDP only (no JSON API/mDNS) | No auto-discovery or WLED state sync | WLED discovery is requested |
| Single JSON config, no DB | Full-file rewrite per save (small file) | Multi-user/history needed |
